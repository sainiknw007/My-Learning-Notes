RHEL Linux Boot Process — Step by Step (Simple Version)

When you press the power button, the system goes through several stages before the Linux shell appears.

🪛 1. BIOS / UEFI (Firmware Stage)

What happens:
The firmware (BIOS or UEFI) runs first.
It checks hardware (CPU, RAM, disks, etc.) — called POST (Power-On Self-Test).
Then it looks for a bootable device (hard disk, CD, USB, etc.).

Files involved: None yet (this is firmware-level).

Output: Passes control to the bootloader (GRUB2).

🧩 2. Bootloader Stage (GRUB2)

Program: GRUB2 = GRand Unified Bootloader version 2

Location: /boot/grub2/ (for BIOS) or /boot/efi/EFI/<distro>/ (for UEFI)

What happens:
GRUB loads and shows you the boot menu (kernel options).
It reads grub.cfg to know:

Which kernel image to load (/boot/vmlinuz-<version>)

Which initramfs image to load (/boot/initramfs-<version>.img)

Kernel boot options (like root=, quiet, etc.)

Key files:

/boot/grub2/grub.cfg         ← Bootloader configuration
/boot/vmlinuz-<kernel>       ← Kernel binary
/boot/initramfs-<kernel>.img ← Temporary root filesystem


Role of grub.cfg:
Tells GRUB which kernel and initramfs to load into memory and where to find root filesystem.

🧬 3. Kernel Stage

File loaded:
/boot/vmlinuz-<kernel-version>

What happens:
GRUB loads the Linux kernel into memory.
The kernel is like the brain — it initializes:

CPU, memory, process management

Device drivers (for basic devices)

Mounts a temporary root filesystem (from initramfs)

But wait:
At this point, your real root filesystem (/) is not mounted yet — so the kernel uses a temporary filesystem from initramfs.

🧰 4. Initramfs Stage (Role of dracut)

File loaded: /boot/initramfs-<kernel>.img

Who creates it: dracut

Purpose: Provides the temporary root filesystem used before the real / is available.

🔹 What’s Inside initramfs?

Essential drivers (storage, filesystem, network)

Scripts to detect disks

Tools to mount the real root filesystem (like LVM, RAID, etc.)

🔹 What happens in this stage:

The kernel mounts initramfs in memory.

Scripts inside initramfs (made by dracut) find your actual root partition (e.g., /dev/mapper/rhel-root).

The real root (/) is mounted.

Control is handed off to /sbin/init (or nowadays systemd).

Role of dracut:
dracut builds that initramfs image.
Without it, Linux wouldn’t know how to mount your root disk during boot.

⚙️ 5. Real Root Filesystem Mounting

What happens:
Once the initramfs scripts find your real root filesystem, they:

Mount it on /

Switch the root from temporary initramfs → real root partition

Location:
Typically /dev/mapper/rhel-root or /dev/sdaX

🚀 6. systemd Initialization (User Space)

File started: /sbin/init → now replaced by /lib/systemd/systemd

What happens:
systemd starts the system processes (services and targets):

Mounts remaining filesystems

Brings up network

Starts services (sshd, NetworkManager, etc.)

Displays login prompt or GUI

💻 7. Login Prompt (Target Reached)

You see:

Console login prompt (multi-user.target)

Or graphical login (graphical.target)

At this point, the boot process is complete.

🧩 Summary — RHEL Boot Process in 7 Steps
Step	Component	Key Files	Purpose
1	BIOS/UEFI	—	Hardware check, load bootloader
2	GRUB2 Bootloader	/boot/grub2/grub.cfg	Loads kernel + initramfs
3	Kernel	/boot/vmlinuz-*	Initializes hardware, loads initramfs
4	Initramfs (dracut)	/boot/initramfs-*.img	Mounts real root filesystem
5	Root Mount	/dev/mapper/...	Mounts real / filesystem
6	systemd	/sbin/init	Starts system services
7	Login	/etc/systemd/system/...	User can log in
🧠 Role of Key Players
Component	Role	Created by
grub.cfg	Tells GRUB which kernel/initramfs to load	Generated by grub2-mkconfig
initramfs	Temporary root filesystem	Created by dracut
vmlinuz	The Linux kernel	Installed via kernel package
systemd	Boot service manager	Part of OS
